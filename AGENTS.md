# Development

This repository (nanocodexyz/egress, private) is `nanocode-egress`, an extension of gakonst/nanocode-ts that runs nanocode agents on a user's own ChatGPT or Claude plan on Cloudflare Workers and Vercel: it signs the user in, keeps the plan's OAuth credential sealed and owned in one place, and injects it into the session's model requests at the egress, so the agent's runtime never holds it. It follows nanocode-ts's TypeScript conventions (namespace modules, `.ts` imports, factories rather than classes except Durable Objects, option bags, TSDoc on exports). Check with `npm run check:types` and `npm test` (`node --test` over `test/*.test.ts`, with mocked OAuth and provider endpoints), and `npm run build` writes `dist/`, which `prepare` builds when the package is installed from Git.

## Library

- `ChatGpt` and `Claude` port the nanocode SDK's `ChatGptSubscription` (crates/backends/codex/client/src/auth/subscription.rs) and `ClaudeSubscription` (crates/backends/claude/client/src/subscription.rs) with the same endpoints, OAuth clients, scopes, stored JSON and refresh rules: ChatGPT's device authorization at auth.openai.com (`start` returns the code for `/codex/device`, `status` polls after the interval, refreshes single-flight per generation, a stale rejection does not refresh twice), and Claude's PKCE authorization at claude.com with Anthropic's manual code page (`start`, `complete` with the pasted `code#state` or the callback URL, profile validation, account on hold, refreshes that keep the account and organization, `reject` after a 401, sign-out that revokes the refresh token). Claude's envelope binding is the SHA-256 of the configuration in the SDK's field order, so state is interchangeable with the SDK's.
- `Store` is the host contract (per-key compare-and-swap over `{ revision, payload }`, `Store.memory()` for tests), `Vault` seals payloads with AES-256-GCM under an HKDF key from a deployment secret of at least 32 characters, bound to the store key (`Vault.sealed(store, vault)`), and `Plans.account(store, { account })` is one account's two plans behind `Plans.Account`: `status`, `signedIn`, `signIn`, `complete`, `signOut`, `inject(provider)` (the credential headers and the generation a rejection names) and `rejected`.
- `Egress` serves only the plans' endpoints (`https://api.anthropic.com/v1/messages` and `/count_tokens` with `?beta=true`, `https://chatgpt.com/backend-api/codex/responses` and `/compact`), drops the request's own credentials, cookies and hop-by-hop headers, injects the plan's (Claude: `authorization` and the `oauth-2025-04-20` beta merged into `anthropic-beta`; ChatGPT: `authorization`, `chatgpt-account-id` and `x-openai-fedramp`), refuses redirects, and retries a request once with a refreshed credential after a 401. `Egress.socket` gives the URL and headers of a Codex WebSocket, which nanocode-ts's WASM opens for every ChatGPT-plan session.
- `Routes.handle` serves the sign-in API for the account a host authenticated: `GET /plans`, `POST /plans/{claude|codex}/sign-in`, `POST /plans/claude/complete` with `{ code }` and `DELETE /plans/{claude|codex}`.

## Cloudflare (`nanocode-egress/cloudflare`)

A `PlanVault` Durable Object per account (`idFromName(account)`) owns that account's plans in its SQLite storage, sealed with `PLAN_SECRET`; one object per account makes refreshes single-flight. nanocode-ts's Cloudflare `App.create` already sends every model request to its `egress` binding with `subscription` in the dispatch, so a deployment wires it as:

```ts
const plans = Egress.durable<Env>((env) => env.PLANS)
App.create({
  egress: Egress.binding({ plans, fallback: (env) => Gateway.create(env.AI, { id: env.AI_GATEWAY_ID }) }),
  subscription: Egress.subscription({ plans }),
})
```

`binding` answers `/model` dispatches with `subscription` from the account's plan and `/socket` (Codex) by opening `chatgpt.com` with the plan's headers, and forwards everything else to `fallback`. chatgpt.com's edge answers HTTP 403 (its HTML "blocked" page) to every request that carries the `cf-worker` header, which workerd adds to each subrequest and a Worker cannot remove, over HTTPS and WebSocket alike, while it serves the same request from Node and Anthropic serves Workers directly; so ChatGPT plans on Workers need `binding`'s `relay(env)`, such as `Egress.relay({ url, secret, fetcher })`, which sends Codex requests and sockets to a `nanocode-egress/relay` server with `x-nanocode-relay-secret`. The relay (`Relay.create({ secret })`, or the `nanocode-egress-relay` binary with `RELAY_SECRET` and `PORT`) is a Node server for a Cloudflare Container or any Node host: it forwards only POSTs and WebSocket upgrades of `/backend-api/codex/responses` and `/compact` without a query to `https://chatgpt.com`, refuses a missing or wrong secret (at least 32 characters) with 401 and other paths with 403, and drops its secret, hop-by-hop, `cf-*` and `cdn-loop` headers. Before it dropped `cf-*`, relayed requests still got 403, because Node forwarded the Worker's `cf-worker`. `nanocode-egress/cloudflare/container` runs the relay in a Cloudflare Container (`@cloudflare/containers`, an optional peer dependency): `RelayContainer` listens on 8080 with the Worker's `RELAY_SECRET` and sleeps 10 minutes after its last request, and `relay(env.RELAY, { secret: env.RELAY_SECRET })` is the `relay` option, reaching the container through its stub's `fetch`, which forwards WebSockets too. Its image is `relay.Dockerfile` at the package root (Node 24 with undici and ws, running `src/relay/main.ts`; build context the package root, which `relay.Dockerfile.dockerignore` limits to the relay's two files). `Egress.routes({ plans, account })` serves the sign-in API, where `account(request, env)` must name the same account as `App.create`'s `authenticate`. `examples/cloudflare` is a Worker with the vault, the relay container, the routes, a `/probe` route that sends one model request through the binding and a `/probe-socket` route that sends one Codex WebSocket message through it; `RELAY_URL` replaces the container with a relay elsewhere. Every route requires `authorization: Bearer <DEMO_TOKEN>` (at least 32 characters; without it the Worker refuses everything) and serves the account `x-demo-account` names, `demo` by default, standing in for a host's own login. `npm run build` there bundles it with Wrangler (13 KiB gzipped on 2026-10-28). To deploy it, put `PLAN_SECRET`, `RELAY_SECRET` and `DEMO_TOKEN` in a JSON file outside the repository and run `npx wrangler deploy --secrets-file <file> --containers-rollout immediate` with Docker running, which builds the linux/amd64 image and pushes it to Cloudflare's registry; the account needs Containers (Tempo Development Resources has them, through the wrangler login in `XDG_CONFIG_HOME=~/.config/nanocode-wrangler-tempo` with `CLOUDFLARE_ACCOUNT_ID=0a39052b0a32ba8c8444345fe21b7595`).

## Vercel (`nanocode-egress/vercel`)

`Redis.store()` keeps the records in Upstash Redis over its REST API (`KV_REST_API_URL` and `KV_REST_API_TOKEN`, as a Vercel Marketplace Redis database sets them), swapping with a Lua script, and `Egress.plans({ store })` seals them with `PLAN_SECRET`. nanocode-ts's Vercel adapter takes a plan per session through `App.create`'s `account(request)` and `subscription` (gakonst/nanocode-ts#167): `Egress.subscription(plans)` returns the account's plan while it is signed in, with `dispatch` and, for Codex, a `socket` over undici's WebSocket (an optional peer dependency, since Node's global WebSocket takes no headers). `Egress.routes({ plans, account })` is a route handler for the sign-in API. `examples/vercel` is one Node function (`api/index.ts`, every path rewritten to it; the Web `Request` keeps the original URL) with the routes and the same `/probe` and `/probe-socket` routes behind `DEMO_TOKEN`, calling the plan's `dispatch` and `socket.open` as nanocode-ts does. Its `.npmrc` sets `install-links`, because Vercel's file tracing leaves out a symlinked `file:../..` dependency and the function then deploys without `nanocode-egress`. To deploy it: `vercel link`, `vercel integration add upstash/upstash-kv` (which sets `KV_REST_API_URL` and `KV_REST_API_TOKEN`; it also writes Upstash agent skills into the directory, which the repository does not keep), `vercel env add PLAN_SECRET` and `DEMO_TOKEN` as sensitive production variables, then `vercel build --prod` and `vercel deploy --prebuilt --prod`.

## Status

Checked on 2026-10-28 with the tests above and nanocode-ts#167's `src/vercel/Harness.test.ts`, where the real WASM runtime sent a signed-in account's requests to `https://api.anthropic.com/v1/messages?beta=true` through the plan's dispatch. The same day `examples/cloudflare` under `wrangler dev`, with the relay on the same Mac, signed a real ChatGPT account in through the device code (its Durable Object records were sealed `v1.` envelopes, with no device code or token in plaintext), and `/probe` and `/probe-socket` got `response.completed` from gpt-6-luna over HTTPS and WebSocket through the relay; without the relay both got 403. The Claude routes answered with a real authorization URL and refused a wrong code with `Claude.InvalidError`. Deployed the same day (the Worker on Tempo Development Resources with the relay in a `lite` container, the Vercel function on tempoxyz with a pay-as-you-go Upstash database in iad1), both refused requests without the token with 401, a real ChatGPT account signed in on each through the device code, and gpt-6-luna answered `pong` with `response.completed` on all four paths: the Worker over HTTPS through the container in 4.4 s (the container's cold start included) and over WebSocket in 2.2 s, and Vercel direct, without a relay, over HTTPS in 2.3 s and over undici's WebSocket in 2.2 s. Whether a third-party deployment may sign users in with their consumer plans is up to Anthropic's and OpenAI's terms; check them before a public demo serves it.

`prototypes/` holds the code this started from, recovered from gakonst/nanocode's history: `examples/cloudflare-egress` at ef31ecf7d~1 (a broker Worker behind a Service Binding with a singleton Codex OAuth Durable Object and placeholder replacement, after iron-proxy), `js/account/worker`'s subscription auth, credential vault and ChatGPT egress at 2d4a4c539~1, and `examples/cloudflare-workers`' subscription egress scripts at bb476038f and 65e92da38.
