# Development

This repository (nanocodexyz/egress, private) prototypes the broker and egress layer that lets nanocode.xyz's Cloudflare and Vercel demos run turns on a visitor's own ChatGPT or Claude plan: the visitor signs in once, the plan's OAuth credential lives only at the outbound boundary (an egress Worker and a Durable Object that owns the rotating credential), and the agent's runtime sees placeholders, never the token. The agents themselves stay in gakonst/nanocode-ts and its demo hosts (gakonst/nanocode-cloudflare-durable, gakonst/nanocode-vercel-durable); the SDK stays in gakonst/nanocode, whose own rules keep managed services out of it.

## What is here

Everything was recovered from gakonst/nanocode's history on 2026-10-28 and has not been built against the current nanocode-ts or SDK; imports still name the old `nanocodex` package.

- `cloudflare/` is `examples/cloudflare-egress` as of ef31ecf7d~1 (2026-08-23): an agent Worker that reaches a private egress Worker through a Service Binding, which applies exact destination and header policies, replaces placeholders with real credentials and keeps one SQLite Durable Object (`CodexOAuthBroker`, named `openai-codex`) as the single owner of a rotating Codex OAuth credential, refreshing it single-flight and never returning its refresh token. It carries over iron-proxy's invariants (exact placeholders, secrets only at the outbound boundary, one durable owner per credential) without Workers for Platforms, DNS interception or TLS interception. Its README describes the policies and deployment.
- `account/` is the per-user subscription layer from `js/account/worker` as of 2d4a4c539~1 (2026-10-13): `subscriptionAuth.ts` (a ChatGPT device sign-in per user with a 15-minute login window and 7-day sessions, stored as `CredentialVault` envelopes with per-operation usage limits), `credentialVault.ts` (envelope encryption of stored credentials), `chatGptEgress.ts` and `chatGptEgressClient.ts` (the ChatGPT egress behind a Container), `subscriptionRuntime.ts` (opening a session on a stored subscription), with their tests, and `subscription-auth.ts` from `examples/cloudflare-workers` at 65e92da38.
- `scripts/` holds the local subscription egress proxy and relay and the Codex auth-file reader from `examples/cloudflare-workers` at bb476038f, with their tests.

## Direction

The demos need, per visitor and per provider: sign-in routes (ChatGPT's device code; Claude's authorization code with PKCE, returned through Anthropic's manual code page), the credential kept encrypted by a single owner that refreshes it, and model requests from the visitor's sessions sent to chatgpt.com or api.anthropic.com with the credential injected at the egress, instead of through the AI Gateway (nanocode-ts's Cloudflare gateway refuses `subscription` dispatches today). The SDK already has the client side: `ClaudeSubscription`, `ChatGptSubscription` and `OpenAiAuth::host_managed_chatgpt()`, which sends no token and expects the transport to inject it. Whether third-party apps may let users sign in with consumer plans is up to Anthropic's and OpenAI's terms, so check them before any of this serves the public demos.
